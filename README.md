# 声控手机助手 (voice_tap)

对着麦克风说出屏幕上的选项文字，程序自动帮你点。为 GRE3000 背单词这类
选择题场景做的，省得一直动鼠标。

识别在**本地离线**跑，不联网、不上传录音。

---

## 快速开始

第一次用，按顺序双击这三个：

| 顺序 | 文件 | 作用 |
|---|---|---|
| 1 | `setup.bat` | 装依赖（只需跑一次） |
| 2 | `probe.bat` | 检查环境、标定麦克风（只需跑一次，换麦克风后要重跑） |
| 3 | `run.bat` | 启动 |

之后就只要双击 `run.bat`。

**使用前**：手机解锁，打开 GRE3000，停在答题界面，scrcpy 正常投屏。

---

## 怎么用

启动后默认是**常驻监听**模式 —— 直接说话就行。

**说法一：说选项里的一部分词。** 不用念完整的。
比如选项是「简单、朴素」，你只说「简单」，它就会点这一项。

**说法二：说序号。** 生僻词听不准时就靠这个：

```
「1」「3」           只说数字
「一」「三」          中文数字
「第一个」「第二个」    带序数词
「选三」「我选2」      带动词
「最后一个」          最后一项
```

**说法三：小键盘。** 按 `F10` 打开，之后小键盘 `1`~`9` 直接点对应选项，
**小键盘 `0` 点「下一题」**（答错或点「不记得了」之后会进详情页，用它继续）。
默认是关的，需要时再开。（`NumLock` 要开着；只认小键盘，主键盘上的数字键不受影响。）

说完稍微停一下（约 0.4 秒），程序会自动切句、识别、点击。

| 按键 | 作用 |
|---|---|
| `F8` | 按住说话，松开即点（需先切到热键模式） |
| `F9` | 在「常驻监听」和「按住说话」之间切换 |
| `F10` | 开关小键盘快捷点击 |
| `ESC` 或 `Ctrl+C` | 退出 |

除了选项，还有一组**固定控制语**：说「下一题」「下一词」「下一个」「继续」「next」
中的任意一个，都会直接点「下一题」按钮 —— **走的是固定坐标，不读屏校验**，
答错进详情页后用它继续。这不是「念出屏幕上的字」：除这组控制语外，
屏幕上别的按钮文字（比如「返回」）目前还不能声控。

**想要个窗口？** 双击 `run_gui.bat`（等价于 `run.bat --gui`）会多开一个**置顶浮窗**，
就浮在 scrcpy 旁边。窗口可以随便拖，位置会记住，下次开窗还在原地。里面三块：

- **控制** —— 五个开关（语音、模式、小键盘、点击后预读、语音说下一题）加「强制重新读屏」
  「退出」两个按钮。点一下和按对应的热键**是同一套动作**，不会出现「界面显示开着、
  实际没开」。
- **程序读到的屏幕** —— 程序手里那一屏：题干和它读到的选项。**不显示坐标**，坐标只进日志。
- **我的输入** —— 最近几次「它听到了什么 / 你按了什么」以及结果；没点成功时从这里看原因。

## 什么时候它不会点

设计原则是**宁可漏点，不可错点**。点错会被判错，漏点只要重说一遍。

它拒绝点击的情况：

- **当前不在 GRE3000 答题界面** —— 比如手机停在 QQ 上。它会打印检测到的应用名。
- **屏幕上没有你说的那个词** —— 它会把你屏幕上实际有哪些选项列出来。
- **两次点击间隔太短** —— 防连点。

每次的判断过程都会打在屏幕上：

```
[听到] '清晰'   置信度 -0.40
[屏幕] 题干：degrade
[屏幕] 选项：adj. 清晰易懂的 / adj. 阴郁的，闷闷不乐的 / ...
[匹配] 子串命中：'adj. 清晰易懂的' → 点击坐标 (606, 811)
[点击] 完成
```

**没点成功时看一眼 `[匹配]` 那行就知道是听错了还是屏幕上真没这个词。**

## 命令行参数

通常双击 `run.bat` 就够了，需要时可以在命令行里加参数：

```
python -m voice_tap.main --gui         同时打开置顶浮窗（等价于 run_gui.bat）
python -m voice_tap.main --dump        只抓一次屏幕并打印解析结果，不识别不点击
python -m voice_tap.main --calibrate   量出当前界面的坐标，生成配置片段
python -m voice_tap.main --preview     不真点，把要点的位置画红圈存到 debug\ 下
python -m voice_tap.main --once        只说一句就退出
python -m voice_tap.main --mode hotkey     以热键模式启动
python -m voice_tap.main --device 1    指定麦克风序号
```

**`--dump` 最有用**：不开口也能验证「手机现在停在哪、选项读到没有」。
**`--calibrate`**：站在任意界面上跑一次，它会告诉你这个界面上的坐标。

也可以直接双击 `run.bat` 后加参数，比如把 `run.bat` 拖进命令行再打 `--dump`。

## 配置

改 `config.yaml`，不用改代码。常用的几个：

| 配置项 | 默认 | 说明 |
|---|---|---|
| `audio.input_device` | `1` | 麦克风序号。换设备后用 `mic_level.bat` 查新序号 |
| `audio.vad_threshold` | `0.0246` | 多大声音算「你在说话」。已按你的麦克风标定过 |
| `asr.model` | `small` | 识别模型。觉得不准换 `medium`，嫌慢换 `base` |
| `hotkey.numpad_enabled` | `false` | 小键盘模式是否默认开启 |
| `hotkey.fixed_next_position` | `[909, 2476]` | 「下一题」按钮的固定坐标 |
| `prefetch.after_click` | `true` | 点击后在后台预读下一屏，省掉等待 |
| `prefetch.click_delay_ms` | `300` | 点击后等多久开始预读（毫秒） |
| `run.default_mode` | `listen` | 启动模式 |
| `match.pinyin_enabled` | `true` | 拼音容错（同音字听错也能救回来） |

### 关于「预读」

读屏（读手机界面）是整条链路上最慢的一环。所以程序会**趁你不用的时间提前读好**：

点完一个选项之后，App 会翻页。翻页那一小段、加上你思考下一题的那几秒，
程序都在闲着 —— 它就拿这段时间去把下一屏读好。等你开口时，界面数据已经在手上了。

**它不会读错。** 不是「等固定时间就当翻好了」，而是读一次、拿界面指纹和点击前比对，
**不一样了才算数**；一样就再等等再读。否则就会拿着旧坐标去点新题目。

日志里能看到它在干什么：

```
[预读] 第 1 次读到新界面，距点击 420 毫秒（本次读屏 380 毫秒）
```

看到「第 1 次」就说明等待时间配得刚好；老是「第 2 次」「第 3 次」，
就把 `prefetch.click_delay_ms` 调大一点。

### 关于「下一题」

答错或点「不记得了」之后，GRE3000 会翻到词汇详情页，得点一下「下一题」才能继续。
**小键盘 `0` 绑的就是它**，也可以直接说「下一题」。

这个按钮**用的是固定坐标**，已实测标定好：

```yaml
hotkey:
  fixed_next_position: [909, 2476]
```

和选项不同，它在页面底部，是固定位置的控件 —— 不会随题干长短漂移，所以可以放心固定。

如果哪天发现按 `0` 点不到（比如换了手机、改了分辨率、或者详情页上它其实在别处），
把这一行改成 `null`，程序就会改成每次读屏去找按钮（更稳，慢一点）。
重新量坐标：

```
python -m voice_tap.main --calibrate
```

### 为什么选项不用固定坐标

我试过，结论是**不能用**。

选项位置大体固定 —— 实测五个选项在 `811 / 999 / 1187 / 1375 / 1563`，
严格等差、间距 188。**但会随题干长短整体偏移**：同一台设备上，第 4 个选项
见过 `1375` 和 `1418` 两个位置（差 43 像素），而行高只有 150 ——
偏移已经吃掉大半余量，题干再长就可能点歪，而且**你不会察觉**，
因为它点了、没报错、只是位置不对。

关键点在于：**读一次屏就同时拿到文字和当前坐标**，两者是同一个数据里出来的。
省掉读屏等于把「精确」换成「猜」—— 这是亏的。

所以选项只有一条路：读屏 → 点。要提速就优化读屏本身（已经合并成一次 adb 往返，
比原来少一次进程创建）。

## 出问题时

| 现象 | 怎么办 |
|---|---|
| 说半天没反应 | 跑 `mic_level.bat`，对着麦克风说话，看哪一行的柱子动 |
| 总点错选项 | 看日志里 `[听到]` 那行 —— 多半是识别错了。试试把 `asr.model` 换成 `medium`，或者**直接说序号**（「1」「第二个」） |
| 生僻词老是匹配不上 | **直接说序号**，比说那个词可靠得多 |
| 小键盘没反应 | NumLock 没开。按一下 NumLock 键，程序也会给出提示 |
| 小键盘按了却点到别的地方 | 确认手机停在 GRE3000 答题界面；选项超过 9 个时，第 10 个以后没法用小键盘点 |
| 答错了卡在详情页出不来 | 按小键盘 `0`，或者直接说「下一题」 |
| 说了「下一题」但没点 | 按钮文字可能不在识别列表里。跑一次 `--calibrate`，把屏幕文字发我 |
| 提示「不在 GRE3000 答题界面」 | 把手机切回答题界面 |
| 一直提示「没找到」 | 看它列出的选项，确认你要说的词确实在里面 |
| adb 连不上 | 确认 scrcpy 能正常投屏；数据线要选「传输文件」模式 |
| 双击 .bat 窗口一闪而过 | 日志在 `debug\launcher_log.txt` |
| 界面（浮窗）关不掉 | 先点窗口右上角的 `X`。窗口 `X`、界面上的「退出」、`ESC` 三条路都汇到同一处收尾；万一都不行，就直接改用 `run.bat`（不带界面）跑 |

排查工具：

- `mic_level.bat` —— 实时显示每路麦克风的电平
- `mic_test.bat` —— 逐个试所有麦克风，报告哪个能用
- `probe.bat` —— 完整体检：环境、界面读取、麦克风标定、识别自检
- 每次运行的日志在 `debug\run_<时间戳>.log`

## 跑测试

```
python -m unittest discover -s tests
```

308 个测试，覆盖这些方面：

- **匹配引擎** —— 三级文字匹配、序号匹配、多候选消歧、最小长度门槛、脏输入、控制语识别
- **无障碍树解析** —— 真实界面数据的解析、前台应用护栏、坐标计算、详情页与「下一题」识别
- **音频采集** —— 用假音频设备模拟「安静→说话→安静」，验证 VAD 切句、预滚缓冲、
  单句上限、数组形状（这块真机上测不了，只能靠测试兜底）
- **小键盘** —— 验证只截小键盘、主键盘数字被放过；开关、0 键下一题、NumLock 提示
- **配置** —— 坐标各种写法、配置写歪了也不能拦死程序
- **预读界面** —— 翻页检测、缓存时效、不该读的时候不读
- **界面状态** —— `UiState` 这块线程安全的状态黑板：主逻辑往上写、界面定时来读，
  以及反方向的意图队列（界面按钮 → 主逻辑）
- **完整链路** —— 从「听到一句话」或「按下小键盘」到「点击坐标」，用真实界面数据，不需要真机
- **测试清单** —— 防止测试被误删而没人发现（这个真的发生过，见 `tests/test_inventory.py`）

`voice_tap/gui.py`（Tkinter 窗口本身）**没法自动测** —— 摆控件、渲染都要真实显示器，
只能上机冒烟。所以这一层刻意做得极薄：逻辑一律放在 `ui_state.py` / `main.py` 里
由上面的测试覆盖，`gui.py` 只负责照状态画一遍。

## 已知限制

- 目前只支持 **GRE3000**（靠它的 resource-id 精确定位选项）。
  其他 App 会走前台护栏被拒绝 —— 这是有意的，避免在别的界面上乱点。
- 手机的屏幕分辨率变了（换手机、改分辨率）需要重跑 `probe.bat`。
- 多邻国这类自绘界面（Flutter）读不到文字，需要第二期接入 OCR 才能支持。
